1-2. 그래프 한글 폰트 설정

matplotlib의 기본 글꼴은 한글을 지원하지 않아서 한글이 □□□처럼 깨집니다. 운영체제에 맞는 한글 글꼴을 지정합니다.

예제 1-2 
import platform
if platform.system() == 'Windows':   font_name = 'Malgun Gothic'   # 윈도우 → 맑은 고딕
elif platform.system() == 'Darwin':  font_name = 'AppleGothic'     # 맥 → 애플고딕
else:                                font_name = 'NanumGothic'     # 리눅스/코랩 → 나눔고딕

sns.set_theme(style='whitegrid', font=font_name)   # 스타일 + 글꼴 함께 지정
plt.rcParams['axes.unicode_minus'] = False         # 마이너스(-) 기호 깨짐 방지
주의sns.set_theme()은 글꼴 설정을 초기화합니다. 글꼴은 반드시 set_theme(font=...) 안에 함께 넣거나, set_theme() 뒤에 설정하세요.

1-3. 데이터 주소 지정 (깃허브에서 바로 내려받기)

데이터 파일을 따로 내려받을 필요 없이, 깃허브에 올려 둔 CSV를 URL로 바로 읽습니다. 내 PC, 주피터, 구글 코랩 어디서든 똑같이 실행됩니다.

예제 1-3 
DATA_URL = 'https://raw.githubusercontent.com/sinaboro/data/main/titanic_kaggle.csv'
df = pd.read_csv(DATA_URL)    # 주소를 넣으면 내려받으면서 바로 읽어 줌
  • raw.githubusercontent.com 주소는 깃허브 웹페이지가 아니라 파일의 원본 내용(raw)만 돌려줍니다. read_csv()에는 반드시 raw 주소를 넣어야 합니다.
  • 주소 형식: https://raw.githubusercontent.com/<계정>/<저장소>/<브랜치>/<파일이름>
  • 인터넷이 안 되면 titanic_kaggle.csv를 노트북과 같은 폴더에 두고 DATA_URL = "titanic_kaggle.csv"로 바꿔 씁니다.
해설 · 1장에서 자주 생기는 문제
  • HTTPError: 404 — URL 오타이거나 깃허브에 파일이 아직 없는 경우. 브라우저로 주소를 한 번 열어 보세요.
  • 예제 2-1 셀은 열 이름을 검사해서, 형식이 다른 파일이면 "⚠ 이 예제와 다른 형식의 파일입니다"를 출력합니다. seaborn 버전 titanic.csv(열 이름 소문자, Name·Cabin 없음)를 읽으면 3장에서 KeyError가 나니 titanic_kaggle.csv를 쓰세요.
  • 학교·기관 네트워크에서 깃허브가 막혀 있으면 CSV 파일을 직접 받아 로컬 경로로 읽습니다.

2데이터 불러오기 & 첫인상 살펴보기

데이터 분석의 첫 단계는 "이 데이터가 어떻게 생겼는지" 아는 것입니다. 처음 보는 데이터를 만나면 항상 아래 네 가지를 확인하세요.

확인할 것코드알 수 있는 것
몇 행, 몇 열?df.shape(891, 12) → 승객 891명, 정보 12가지
실제 값은?df.head(), df.tail(), df.sample()각 열에 어떤 값이 들어 있는지
자료형과 빈 값은?df.info()열별 자료형, 비어 있지 않은 값의 개수
숫자 열의 분포는?df.describe()평균, 최솟값, 최댓값, 사분위수

df = pd.read_csv(DATA_URL)       # 깃허브의 CSV 를 읽어서 DataFrame(표)으로 만들기

2-3. 구조와 요약 통계 확인

예제 2-2, 2-3

df.describe().round(2)           # 숫자 열 요약 통계 (소수 둘째 자리까지)

info() 결과에서 Non-Null Count가 891보다 작은 열이 결측치가 있는 열입니다.

열개수평균최솟값중앙값최댓값
Survived8910.38001
Pclass8912.31133
Age71429.700.4228.0080.00
Fare89132.200.0014.45512.33
생각해보기
  1. Survived의 평균이 0.38입니다. 이 숫자는 무엇을 의미할까요? (힌트: 0과 1로만 된 열의 평균)
  2. Fare의 최댓값(512)과 중앙값(14.45)을 비교해 보세요. 무엇을 알 수 있나요?
  3. Age의 개수가 891이 아니라 714인 이유는?
해설
  1. 전체 승객 중 생존자 비율 = 약 38.4%. "0/1 열의 평균 = 1의 비율"은 4장에서 groupby().mean()으로 생존율을 구하는 핵심 개념입니다.
  2. 일부 승객이 매우 비싼 표를 샀다 → 오른쪽으로 치우친 분포·이상치. 평균(32.2)이 중앙값(14.45)보다 훨씬 큰 이유도 같습니다.
  3. 나이를 모르는 승객이 177명 → 3장 결측치 처리로 연결됩니다.

3결측치(빈 값) 처리

현실의 데이터에는 빈 값(결측치, NaN)이 자주 있습니다. 그대로 두면 평균 계산, 그래프, 머신러닝에서 문제가 생기므로 찾아내고 → 이유를 생각하고 → 적절히 처리해야 합니다.

처리 방법언제 쓰나?코드
삭제빈 값이 너무 많거나, 아주 조금일 때dropna(), drop()
대표값으로 채우기숫자 → 평균/중앙값, 문자 → 최빈값fillna()
그룹별 대표값으로 채우기그룹마다 값의 차이가 클 때groupby().transform()

3-1. 결측치 개수와 비율 확인

예제 3-1 
df.isnull().sum()          # 빈 값이면 True(1) → 더하면 열별 결측치 개수
df.isnull().mean() * 100   # 평균을 내면 결측치 비율(%)
열결측치 수비율처리 방법
Cabin68777.1%너무 많이 비어 있음 → "객실 정보 있음(HasCabin)" 열만 만들고 삭제
Age17719.9%중요한 정보 → 그룹별 중앙값으로 채우기
Embarked20.2%단 2개 → 최빈값(S)으로 채우기

3-2. Embarked : 최빈값으로 채우기

예제 3-2 
most_common_port = df['Embarked'].mode()[0]   # 최빈값 (결과가 Series 라서 [0]으로 꺼냄)
df['Embarked'] = df['Embarked'].fillna(most_common_port)   # 결과를 꼭 다시 대입!

3-3. Cabin : 파생 변수를 만들고 삭제

예제 3-3 
df['HasCabin'] = df['Cabin'].notnull().astype(int)   # 값이 있으면 1, 없으면 0
df = df.drop(columns=['Cabin'])                      # Cabin 열 삭제

객실 번호가 기록된 승객의 생존율은 66.7%, 기록이 없는 승객은 30.0%였습니다. 빈 값 자체가 정보가 될 수도 있습니다 (→ 10장 인사이트 ⑤).

3-4. Age : 그룹별 중앙값으로 채우기

전체 중앙값(28세) 하나로 채울 수도 있지만, 객실 등급·성별에 따라 나이 차이가 큽니다.

객실 등급여성 중앙값남성 중앙값
1등석35.0세40.0세
2등석28.0세30.0세
3등석21.5세25.0세
예제 3-4 
# transform('median') : 그룹별 중앙값을 '원래 행 개수(891 개) 그대로' 각 행에 붙여 줌
group_median_age = df.groupby(['Pclass', 'Sex'])['Age'].transform('median')
df['Age'] = df['Age'].fillna(group_median_age)   # 빈 칸만 그룹 중앙값으로 채워짐
df.isnull().sum().sum()                          # 0 이면 모든 결측치 처리 완료!
agg 와 transform 의 차이
  • groupby().median() → 그룹 수만큼(6행) 결과가 나옴 → fillna에 바로 못 넣음
  • groupby().transform("median") → 원래 행 수(891행) 그대로 결과가 나옴 → fillna에 바로 넣을 수 있음
생각해보기
  1. Cabin의 결측치를 최빈값으로 채운다면 어떤 문제가 생길까요?
  2. Age를 평균이 아니라 중앙값으로 채운 이유는 무엇일까요?
해설
  1. 77%의 승객이 모두 같은 객실에 묵은 것처럼 되어 데이터가 심하게 왜곡됩니다. "채울 수 있다 ≠ 채워야 한다".
  2. 중앙값은 극단값(이상치)의 영향을 덜 받기 때문입니다. 나이는 차이가 작지만 Fare 같은 치우친 데이터에서는 차이가 큽니다.
자주 하는 실수
  • df["Age"].fillna(28)만 하고 대입을 안 함 → 반환값을 대입해야 함
  • inplace=True 사용 → 판다스 3에서는 원본이 바뀌지 않음 (Copy-on-Write)
  • groupby().median() 결과(6행)를 fillna에 넣음 → 행 개수가 달라서 안 됨
심화 6장에서 호칭(Title)을 뽑은 뒤, 호칭별 중앙값으로 다시 채워 보세요.

5다변수 분석

성별도 중요하고 등급도 중요했습니다. 그렇다면 "3등석 여성"과 "1등석 남성" 중 누가 더 많이 살아남았을까요? 두 개 이상의 조건을 함께 비교할 때는 pivot_table과 crosstab을 사용합니다.

5-1. pivot_table : 엑셀 피벗 테이블처럼

예제 5-2 
pd.pivot_table(df,
               index='Sex',        # 행(세로) 기준
               columns='Pclass',   # 열(가로) 기준
               values='Survived',  # 계산할 값
               aggfunc='mean')     # 계산 방법 (평균 = 생존율)
성별 \ 등급1등석2등석3등석
female96.8%92.1%50.0%
male36.9%15.7%13.5%

1·2등석 여성은 90% 이상 생존했지만, 2·3등석 남성은 15% 안팎에 그쳤습니다. 3등석 여성(50%)이 1등석 남성(37%)보다 생존율이 높습니다 → 성별의 영향이 등급보다 컸습니다.

해설 df.groupby(["Sex","Pclass"])["Survived"].mean().unstack()의 결과가 pivot_table과 같습니다. 즉석 퀴즈: aggfunc를 "count", "sum"으로 바꾸면? → 승객 수, 생존자 수

5-2. crosstab : 두 범주의 교차표

예제 5-3 
pd.crosstab(df['Embarked'], df['Pclass'], margins=True)          # 개수 + 합계
pd.crosstab(df['Embarked'], df['Pclass'], normalize='index')     # 행(항구)별 비율
항구 \ 등급1등석2등석3등석
C50.6%10.1%39.3%
Q2.6%3.9%93.5%
S20.0%25.4%54.6%
핵심 정리
  • C 항구 승객은 절반 이상이 1등석이었습니다. C 항구의 생존율이 높았던 것은 항구 때문이 아니라 1등석 승객이 많았기 때문입니다.
  • 상관관계 ≠ 인과관계: 두 값이 함께 움직인다고 해서 하나가 다른 하나의 원인인 것은 아닙니다.

6-3. FareBand : pd.qcut 으로 4등분

cut vs qcut
  • pd.cut : 값의 범위를 기준으로 나눔 (자로 재기) → 구간마다 사람 수가 다를 수 있음
  • pd.qcut : 사람 수가 같아지도록 나눔 (줄 세우기) → 4등분이면 각 구간에 약 25%씩
예제 6-3 
df['FareBand'] = pd.qcut(df['Fare'], 4, labels=['저가', '중저가', '중고가', '고가'])

요금 등급별 생존율: 저가 19.7% → 중저가 30.4% → 중고가 45.5% → 고가 58.1%. 비싼 표일수록 생존율이 높습니다.

6-4. Title : 이름에서 호칭 뽑기

이름 형식은 "성, 호칭. 이름"입니다. 예) Braund, Mr. Owen Harris → 쉼표와 마침표 사이를 뽑으면 호칭!

예제 6-4 
df['Title'] = df['Name'].str.extract(r',\s*([^\.]+)\.', expand=False)   # 쉼표~마침표 사이
df['Title'] = df['Title'].replace({'Mlle': 'Miss', 'Ms': 'Miss', 'Mme': 'Mrs'})
main_titles = ['Mr', 'Miss', 'Mrs', 'Master']
df['Title'] = np.where(df['Title'].isin(main_titles), df['Title'], 'Rare')  # 나머지는 Rare
호칭의미승객 수평균 나이생존율
Mr성인 남성51731.3세15.7%
Master어린 남자아이406.6세57.5%
Miss미혼 여성18521.9세70.3%
Mrs기혼 여성12634.7세79.4%
RareDr, Rev, Col 등2345.3세34.8%

같은 남성이라도 Master(남자아이)는 생존율이 Mr의 3배 이상입니다 → "어린이 먼저" 원칙의 증거!

해설
  • 정규표현식은 "쉼표와 마침표 사이를 뽑는다" 정도로 이해하면 충분합니다. 정규식 없는 대안: df["Name"].str.split(",").str[1].str.split(".").str[0].str.strip()
  • np.where는 넘파이 수업 내용이 실전에서 그대로 쓰이는 대표 사례입니다.
  • 범주형(pd.cut 결과) 열로 groupby할 때 observed=True를 주면 실제로 존재하는 그룹만 계산하고 경고를 막습니다.

8발견한 사실 & 간단한 생존 예측

8-1. 지금까지 발견한 사실

요인발견한 사실
성별여성 생존율(74%)이 남성(19%)보다 압도적으로 높다 → 가장 강력한 요인
객실 등급1등석(63%) > 2등석(47%) > 3등석(24%). 높은 등급일수록 생존율이 높다
나이어린이(특히 Master 호칭의 남자아이)는 생존율이 높았다
가족 수2~4인 가족이 가장 높고, 혼자이거나 5인 이상이면 낮았다
탑승 항구C 항구 생존율이 높았지만, 1등석 비율이 높았기 때문이다 (상관 ≠ 인과)

이 표는 "무엇이 관련 있었나"라는 사실입니다. 이 사실들이 서로 어떻게 얽혀 있고 무엇을 의미하는지는 10장 인사이트에서 한 단계 더 깊이 들어갑니다.

8-2. 우리가 찾은 규칙으로 생존 예측하기

머신러닝 없이, 분석에서 찾은 규칙만으로 생존 여부를 맞혀 봅니다. 정확도 = 예측이 맞은 승객 수 ÷ 전체 승객 수입니다.

예제 8-1 ~ 8-3 
y = df['Survived'].values                                   # 실제 정답 (넘파이 배열)

# 규칙 0 : 모두 사망했다고 예측
pred0 = np.zeros(len(df), dtype=int)
(pred0 == y).mean()                                         # 맞힌 비율 → 61.6%

# 규칙 1 : 여성은 생존, 남성은 사망
pred1 = np.where(df['Sex'] == 'female', 1, 0)
(pred1 == y).mean()                                         # 78.7%

# 규칙 2 : 규칙 1 + 예외 (3 등석 대가족 여성은 사망, 1·2 등석 남자아이는 생존)
is_female      = df['Sex'] == 'female'
is_poor_bigfam = (df['Pclass'] == 3) & (df['FamilySize'] >= 5)
is_rich_boy    = (df['Title'] == 'Master') & (df['Pclass'] <= 2)
pred2 = np.where((is_female & ~is_poor_bigfam) | is_rich_boy, 1, 0)
(pred2 == y).mean()                                         # 82.4%
주의 여러 조건은 &(그리고), |(또는), ~(아니다)로 연결하고, 조건마다 괄호( )를 꼭 쳐야 합니다. 파이썬의 and, or는 판다스/넘파이 배열에 쓸 수 없습니다.
핵심 정리
  • 단순한 규칙만으로도 약 82%의 정확도를 얻었습니다.
  • 데이터에서 패턴을 찾아 규칙을 만드는 과정을 컴퓨터가 자동으로 하게 만든 것이 바로 머신러닝입니다. (다음 단계: scikit-learn의 결정 트리, 로지스틱 회귀)
해설
  • "규칙 0(모두 사망)도 61.6%나 맞힌다"는 점이 중요합니다. 정확도는 기준선(baseline)과 비교해야 의미가 있습니다.
  • 이 정확도는 규칙을 만든 같은 데이터로 평가한 것이라 실제보다 높게 나옵니다 → 11장 조언 ⑤ "검증"에서 자세히 다룹니다.
  • 실습문제 15번(나만의 규칙)으로 정확도 경쟁을 해 보세요.

10타이타닉 데이터가 알려 준 인사이트 5가지

사실은 "여성 생존율 74%"처럼 숫자 그 자체이고, 인사이트는 여러 사실을 엮어 "그래서 무엇을 뜻하는가"를 말하는 것입니다. 아래 다섯 가지는 지금까지 배운 groupby·pivot_table·crosstab만으로 찾을 수 있습니다. 숫자는 모두 891명 전체 데이터(교안 3장 방식으로 결측치 처리) 기준입니다.

① 성별은 등급보다 강했다 — "누구인가"가 "얼마를 냈는가"를 이겼다

1등석 남성의 생존율은 36.9%, 3등석 여성은 50.0%입니다. 가장 비싼 표를 산 남성보다 가장 싼 표를 산 여성이 더 많이 살았습니다. 같은 등급 안에서 남녀 차이는 37~76%p인데, 같은 성별 안에서 1·3등석 차이는 23~47%p입니다. 상관계수도 성별(+0.54)이 등급(-0.34)보다 큽니다.

그래서? 생존을 가른 1순위 규칙은 "여성 먼저"라는 사회적 규범이었고, 돈(등급)은 그 규칙 안에서 두 번째로 작동했습니다. 예측 규칙 1(여성 = 생존)이 단 한 줄로 78.7%를 맞힌 이유입니다.

배운 기술 : pivot_table(index='Sex', columns='Pclass') — 두 변수를 함께 놓아야 어느 쪽이 더 센지 보입니다.

② "여성과 어린이 먼저"에도 등급의 벽이 있었다

1·2등석 남자아이(Master)는 12명 전원(100%) 살아남았지만, 3등석 남자아이는 28명 중 11명(39.3%)만 살았습니다. 여성도 1·2등석은 92~97%였지만 3등석은 50%에 그쳤습니다. 규범은 모두에게 똑같이 적용되지 않았습니다.

그래서? 전체 평균("Master 생존율 57.5%")은 서로 전혀 다른 두 집단(100% vs 39%)을 섞어 놓은 숫자였습니다. 평균 하나로 집단을 설명하면 그 안의 불평등이 지워집니다. 3등석 객실은 배 아래쪽에 있어 갑판까지 거리가 멀었고, 구명보트에 접근할 기회 자체가 적었던 것으로 해석할 수 있습니다.

배운 기술 : str.extract로 만든 Title 파생 변수 + groupby — 파생 변수가 없었다면 "남자아이"라는 집단 자체를 볼 수 없었습니다.

③ 가족은 2~4명일 때 가장 유리했고, 대가족의 비극은 3등석에 몰려 있었다

혼자 탄 승객 30.4%, 2~4명 가족 57.9%, 5명 이상 대가족 16.1%로 역U자 모양입니다. 그런데 5명 이상 대가족 62명 중 54명(87%)이 3등석이었고, 이들의 생존율은 7.4%에 불과했습니다.

그래서? 작은 가족은 서로 챙기며 함께 보트로 이동할 수 있었지만, 대가족은 흩어진 가족을 모두 찾다가 탈출 시간을 놓쳤을 가능성이 큽니다. 그리고 "대가족이라 위험했다"의 상당 부분은 "3등석이라 위험했다"와 겹칩니다. 숫자 하나(FamilySize)가 실제로는 두 가지 이야기(가족 규모 + 등급)를 함께 담고 있습니다.

배운 기술 : pd.cut으로 구간 만들기 + pivot_table로 등급과 교차 — 관계가 직선이 아닐 때는 구간으로 나눠 보세요.

④ 항구가 사람을 살린 것이 아니다 — 교란 변수 찾기

C(셰르부르) 승객의 생존율은 55.4%로 S(사우샘프턴) 33.9%보다 높습니다. 그런데 C 승객은 51%가 1등석, 43%가 여성이었고, S 승객은 1등석 20%, 여성 32%였습니다. 즉 C 항구의 높은 생존율은 대부분 "누가 탔는가"의 차이입니다. 등급을 고정하고 보면 차이가 크게 줄어듭니다. 다만 등급을 고정해도 C가 조금 더 높은 부분(예: 3등석 38% vs 19%)은 성별 구성 차이와 작은 표본(C 2등석은 17명뿐)이 섞인 결과라, 단정할 수 없습니다.

그래서? "C 항구에서 타면 산다"는 틀린 결론입니다. 두 변수가 함께 움직일 때는 둘 다에 영향을 주는 제3의 변수(교란 변수)가 있는지 먼저 의심해야 합니다. 그리고 집단을 잘게 나눌수록 각 칸의 인원 수(n)를 꼭 함께 확인해야 합니다.

배운 기술 : crosstab(normalize='index')로 구성 비율 보기 + pivot_table로 조건 고정하기

⑤ 빈 값도 정보다 — 기록이 남은 사람과 남지 않은 사람

객실 번호(Cabin)가 기록된 승객은 생존율 66.7%, 기록이 없는 승객은 30.0%입니다. 하지만 이것은 객실 번호가 사람을 살린 것이 아닙니다. 1등석은 81%가 객실 번호가 기록됐지만 3등석은 2.4%뿐입니다. 나이(Age)도 마찬가지로, 나이 기록이 없는 승객의 생존율(29.4%)이 있는 승객(40.6%)보다 낮은데, 나이 기록이 없는 177명 중 136명(77%)이 3등석입니다.

그래서? 결측치는 무작위로 생기지 않습니다. "누구의 정보가 기록되었는가" 자체가 그 사람의 사회적 위치를 보여 줍니다. 그래서 결측치를 무작정 지우면(dropna) 3등석 승객이 집중적으로 빠져 결과가 1등석 쪽으로 기울고, HasCabin처럼 "비어 있음"을 하나의 변수로 만들면 오히려 예측에 도움이 됩니다.

배운 기술 : isnull()로 결측 여부를 0/1 변수로 만들고 → groupby로 결측 집단의 특징 비교

다섯 인사이트를 한 문장으로 타이타닉의 생존은 운이 아니라 "성별 → 등급 → 나이·가족 구성" 순서의 구조를 따랐고, 겉으로 보이는 다른 요인(항구, 객실 기록)의 상당 부분은 이 구조가 다른 모습으로 드러난 것이었습니다.

11데이터 분석, 이렇게 하세요 — 타이타닉에서 배운 7가지 조언

문법은 검색하면 나오지만, 분석하는 태도와 순서는 직접 해 봐야 몸에 남습니다. 오늘 타이타닉 분석에서 실제로 겪은 장면을 바탕으로, 다른 어떤 데이터를 만나도 써먹을 수 있는 방법을 정리합니다.

1

코드보다 질문을 먼저 쓰세요

이 수업은 "누가 살아남았고, 왜?"라는 질문 하나로 시작했습니다. 질문이 있어야 어떤 열을 보고 어떤 그래프를 그릴지 정해집니다. 질문 없이 describe()부터 돌리면 숫자는 많아지는데 결론이 없습니다.

실천 : 노트북 첫 셀에 질문 2~3개를 적어 두고, 분석이 끝나면 그 질문에 한 문장씩 답하세요.

2

데이터를 믿기 전에 먼저 의심하세요

shape → head → info → describe 네 가지는 매번 확인합니다. 그 덕분에 Age가 714개뿐이라는 것, Fare의 평균(32)이 중앙값(14)보다 훨씬 크다는 것, seaborn 버전 파일은 열 이름이 다르다는 것을 일찍 발견했습니다. 원본은 df_raw = df.copy()로 보관하세요.

실천 : 분석 전에 "이 데이터는 누가, 언제, 어떻게 모았나? 무엇이 빠져 있나?"를 한 줄로 적어 보세요.

3

결측치는 "어떻게 채울까"보다 "왜 비었을까"를 먼저 물으세요

Cabin은 77%가 비어 있어 채우지 않고 HasCabin으로 바꿨고, Age는 등급·성별 그룹 중앙값으로 채웠고, Embarked는 2개라 최빈값으로 채웠습니다. 같은 "빈 값"이라도 처리 방법이 모두 달랐습니다. 그리고 인사이트 ⑤처럼 비어 있다는 사실 자체가 3등석이라는 신호였습니다.

실천 : 결측치를 처리하기 전에 df.groupby(df['열'].isnull())['타깃'].mean()으로 "빈 집단"과 "찬 집단"이 다른지 확인하세요. 처리 후에는 7-2처럼 분포가 왜곡되지 않았는지 그래프로 확인하세요.

4

한 변수로 결론 내리지 말고, 반드시 쪼개 보세요

"C 항구 생존율이 높다"는 한 변수 분석의 결론은 등급으로 쪼개자 대부분 사라졌습니다(인사이트 ④). "Master 생존율 57.5%"도 등급으로 쪼개자 100%와 39%로 갈라졌습니다(인사이트 ②). 평균은 서로 다른 집단을 섞어 버립니다.

실천 : 흥미로운 차이를 발견하면 곧바로 "이것을 등급(또는 성별, 나이대)으로 나눠도 그대로일까?"를 pivot_table로 확인하세요. 칸마다 인원 수(aggfunc='count')도 같이 보고, 20명 미만인 칸의 숫자는 조심해서 말하세요.

5

기준선과 비교하고, 안 본 데이터로 검증하세요

"모두 사망" 규칙도 61.6%를 맞힙니다. 그러니 82%라는 숫자는 기준선보다 약 21%p 나아졌다는 뜻으로 읽어야 합니다. 또 규칙을 만든 데이터로 채점하면 점수가 부풀려집니다. 아래 그림은 결정 트리를 점점 복잡하게 만들었을 때입니다. 깊이 제한이 없는 트리는 본 데이터에서 98%를 맞히지만, 안 본 데이터에서는 78.7%로 단순한 "여성 = 생존" 규칙(78.7%)과 같은 수준입니다. 외워서 푼 것이지 이해한 것이 아닙니다.

실천 : 모든 결과에 "무엇과 비교해서?"를 붙이세요. 예측을 한다면 데이터를 훈련/검증으로 나누고(train_test_split, cross_val_score), 단순한 모델이 비슷한 성능이면 단순한 쪽을 고르세요.

6

상관관계를 인과관계로 말하지 마세요

객실 번호가 기록된 사람이 많이 살았다고 해서 "객실 번호를 기록하면 산다"가 아닙니다. 데이터는 "함께 움직였다"까지만 말해 줍니다. "왜"는 도메인 지식(배의 구조, 당시 구조 원칙)으로 설명하되, 그것이 해석(가설)임을 분명히 하세요.

실천 : 보고서에서 "~때문이다" 대신 "~와 관련이 있다", "~로 해석할 수 있다"를 쓰고, 다른 설명(교란 변수)이 가능한지 한 줄 덧붙이세요.

7

결과는 숫자가 아니라 "그래서?"로 전달하세요

"female 0.742, male 0.189"는 결과이고, "3등석 여성이 1등석 남성보다 많이 살았다 — 성별이 등급보다 강했다"는 인사이트입니다. 그래프는 한 장에 메시지 하나만 담고, 제목에 그 메시지를 쓰세요(10장 그래프 제목들처럼). 같은 의미에는 같은 색을 쓰고(이 교안은 생존=파랑, 사망=주황), 퍼센트에는 인원 수를 함께 표시하세요.

실천 : 모든 그래프 아래에 "이 그래프가 말하는 것"을 한 문장으로 적어 보세요. 한 문장으로 안 써지면 그래프를 다시 그려야 한다는 신호입니다.

B부록 B. 자주 묻는 질문

질문답변
결측치는 항상 채워야 하나요?아닙니다. 비율, 중요도, 결측의 이유를 보고 판단합니다. Cabin처럼 너무 많이 비면 삭제하거나 "있음/없음" 정보만 남깁니다.
평균과 중앙값 중 무엇으로 채우나요?이상치가 있거나 분포가 치우치면 중앙값, 대칭이면 평균도 괜찮습니다. 확실하지 않으면 중앙값이 안전합니다.
groupby에 왜 observed=True를 주나요?pd.cut으로 만든 범주형 열은 데이터에 없는 범주까지 결과에 나올 수 있어서, 실제로 있는 그룹만 계산하도록 하는 옵션입니다.
barplot 막대 위의 검은 선은 뭔가요?신뢰구간(오차 막대)입니다. 수업에서는 errorbar=None으로 숨겼습니다.
82%면 좋은 모델인가요?기준선(61.6%)보다 높으니 의미는 있지만, 같은 데이터로 평가해서 낙관적인 값입니다. 11장 조언 ⑤처럼 훈련/검증을 나눠 평가해야 합니다.
inplace=True는 왜 쓰면 안 되나요?판다스 3부터 Copy-on-Write가 기본이라 df["열"].fillna(..., inplace=True)는 원본을 바꾸지 않습니다. 대입 방식이 가장 확실합니다.
사실과 인사이트는 어떻게 다른가요?사실은 "여성 생존율 74%", 인사이트는 "3등석 여성이 1등석 남성보다 많이 살았다 → 성별이 등급보다 강한 요인"처럼 여러 사실을 엮어 의미를 말하는 것입니다(10장).
이 교안 PDF는 어떻게 다시 만드나요?저장소 루트에서 python handout_src/build.py를 실행하면 그림을 다시 그리고 크롬/엣지로 PDF를 인쇄합니다. 본문은 handout_src/handout.html에서 고칩니다.
